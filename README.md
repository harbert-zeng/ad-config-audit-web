# 广告配置检查 · 分组接入版

**这是已确认的五步分组接入界面代码，分享版使用全新虚构数据。** 保留原有布局和交互，替换客户品牌、负责人姓名、业务网址与硬编码对象 ID。没有上传真实账户快照或历史操作记录。

## 开始运行

需要 Python 3.10+。主流程使用 Python 标准库，不需要 API 密钥。

```sh
python3 server.py --port 8772
```

浏览器打开：

- 五步分组接入：http://127.0.0.1:8772/?step=0&view=group-onboarding
- 能力介绍及 P0：http://127.0.0.1:8772/workflow-v2.html#capabilities
- 首日报告：http://127.0.0.1:8772/first-day/ （先完成接入并保存）
- 阶段规则对话：http://127.0.0.1:8772/phase-rules/

默认 2 个虚构 Campaign、2 个虚构 Ad Set、4 条虚构广告。页面标明示例数据。原本已填写的确认信息不随仓库提供，需要重新体验确认过程。

## 正确的主流程

1. **接入范围**：核对三层状态、账户和广告范围，填写确认人。按对象 ID 关联，名称仅用于展示和规则匹配。
2. **基础规则**：市场、语言、Facebook、Instagram 分别确认。多数值是候选建议，不代表自动获准。预算和首日继承分开确认。
3. **页面匹配**：按落地页分组确认当前页面，或把建议转成名称匹配规则。显示具体 URL 和对应 Campaign／Ad Set／Ad。空 URL 不成为标准。
4. **例外与缺口**：已知不符、缺规则、缺数据分开呈现；负责人理解缺口后才能保存试运行版本。
5. **首日版本**：保存规则、来源快照和未完成项，进入首日报告。首次接入没有上一期，不把全部广告视为新增。
6. **阶段规则**：输入允许词／禁止词 → 整理草稿 → 补齐范围、日期和确认人 → 确认保存 → 对当前快照试查。只列待暂停广告，由投手操作。

## 当前边界与未接通部分

- AI Creative／Related media 暂不纳入主流程的检查能力；Media Plan 核对与发送飞书暂缓。
- 规则对话目前是明确关键词解析，不是已接通大模型的 Agent；不自动判断折扣、翻译或图片语义。
- `server.py` 的五步接入状态与 `lifecycle.py` 的新工作流状态目前独立。Daily 原型不能冒充已经打通的每日生产闭环。
- `/daily/` 是独立虚构交互演示；`/media-plan/` 是遗留实验模块。保留代码供开发追溯，不是当前主入口。
- `/api-setup/` 保留通用只读 API 连接代码，但未配置任何账户或密钥。它不代表已实现全量自动取数或每日调度。
- 目前没有多人登录、权限隔离、生产数据库、自动调度。服务只监听本机，不能直接作为公网部署服务。

## 数据与迁移

运行产生的确认、版本与记录写入 `local-data/`，已加入忽略列表。默认快照 `dist/data.json` 为虚构数据，由 `tools/generate_demo.py` 从零生成，不是脱敏后的真实广告记录。

开发同事若要导入真实快照，请把文件放在仓库外：

```sh
python3 server.py --port 8772 --source-file /private/location/source.json --data-dir /private/location/review-state
```

换数据时使用新的保存目录，防止不同账户或快照混用。接口密钥仅驻留进程内存；连接地址和探测响应可能包含业务信息，运行目录不要上传。

当前页面顶部的品牌／示例标记为分享版展示标识；接真实数据开发时，应以数据来源动态显示，并保留采集时间。
